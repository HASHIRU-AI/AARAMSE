\subsection*{2. The Proposed Future Agentic State (Solution)}

\begin{sloppypar}
We introduce \textbf{AARAMSE} (\textbf{A}dvisory \textbf{A}gent \textbf{R}efusal-\textbf{A}ware
\textbf{M}iddleware for \textbf{S}emantic \textbf{E}qualization), a model-agnostic
layer that sits in front of a deployed financial AI agent. AARAMSE builds on our
open-source NAAMSE framework \cite{pai2026naamse}.
\end{sloppypar}

AARAMSE has no parameter access and does no retraining, so a refusal is
\emph{observed, not predicted}: the layer probes the deployed model, and only a
query the model actually refuses enters the repair path --- everything else is
passed through byte-identical. For a refused query it isolates the minimal
refusal-triggering fragment (mRTF), applies a \textbf{certified} operator to that
fragment alone, re-probes to confirm the user received an answer, and escalates
to a human when no certified operator clears the refusal.

The safety control is not a classifier deciding which requests are benign; at
runtime no such judgement is reliable, and staking the boundary on one
reintroduces the model-judgement variance the layer exists to remove. The
control is \emph{certification}.

\medskip
\noindent\textbf{Core Technical Contributions:}
\begin{itemize}
    \item \textbf{Measurement first.} Binary refusal detection cannot measure
    over-refusal \cite{rottger2024xstest}: under a compliance system prompt the
    dominant behaviour is \emph{partial} refusal --- decline, then answer anyway.
    We implement XSTest's three-way taxonomy as an offline instrument and keep it
    strictly off the runtime safety path.
    \item \textbf{Localization with structural confinement.} Delta debugging
    \cite{zhou2026ddor} isolates the mRTF at sentence then word granularity.
    Where DDOR \emph{instructs} a model to edit only that fragment, our model
    returns a replacement phrase and the substitution happens in code, so every
    token outside the mRTF is byte-identical by construction rather than by the
    model's compliance.
    \item \textbf{Certification against the deployed model.} Each operator is
    certified on contrastive benign/prohibited pairs \emph{on the model it will
    front}. A certificate is a property of \emph{(operator, model, corpus)}, not
    of the operator: in our runs an operator certified clean against a simulator
    and leaked on its first live query. Enforcement is fail-closed --- an
    uncertified operator is excluded, not trusted.
    \item \textbf{Deterministic invariants and tamper-evident audit.} A hand-built
    actionability lattice rejects any rewrite that raises actionability or drops
    the propositional core; it is deliberately not learned, so no model judgement
    sits on the safety path. A SHA-256 hash-chained log records the operator
    program, the mRTF, each edit, and the certificates in force, giving a
    supervisor a replayable record of every intervention.
\end{itemize}

\subsection*{4. Risks \& Guardrails}

\begin{enumerate}
    \item \textbf{Dual-Use: Rewriting as a Jailbreak Vector}:
    \begin{itemize}
        \item \textit{Risk}: A layer that rewrites prompts to clear a refusal
        boundary is, in the wrong hands, a jailbreak primitive.
        \item \textit{Mitigation}: Four fail-closed controls: only queries the
        model actually refuses are eligible; only operators holding a passing
        certificate on the deployed model may run; edits are structurally confined
        to the mRTF; and the actionability lattice rejects the rest, escalating
        rather than forcing a query through. All interventions are logged, under a
        responsible-use licence.
        \item \textit{The trade-off, stated honestly}: on \texttt{gemma4:12b}
        under an FCA compliance prompt, the confined operator recovered 1/8
        over-refused benign queries and leaked 0/10 prohibited ones, while
        unconfined operators recovered 6--7/8 and leaked 2/10. We therefore
        specify the requirement as an auditable leakage \emph{budget} set by the
        deployer, defaulting to zero with the confined operator, rather than
        claiming utility at no cost. Quantifying that exchange rate per model is
        the sprint deliverable.
    \end{itemize}
    \item \textbf{Model-Judgement Variance}:
    \begin{itemize}
        \item \textit{Risk}: LLM judges disagree inconsistently on regulated-domain
        advice \cite{llmjudges2026inconsistent}; a layer relying on one inherits
        that variance.
        \item \textit{Mitigation}: We remove model judgement from the runtime path
        entirely --- deterministic lattice and refusal-pattern checks plus
        pre-issued certificates decide at runtime, and the LLM judge is confined to
        offline measurement and certification, where its output is auditable after
        the fact rather than load-bearing in production.
    \end{itemize}
    \item \textbf{Measurement Validity}:
    \begin{itemize}
        \item \textit{Risk}: Leak figures rest partly on OR-Bench labels that DDOR
        \cite{zhou2026ddor} criticises as noisy, scored by a general model prompted
        with the taxonomy rather than the published instrument.
        \item \textit{Mitigation}: We report leak rates as upper bounds,
        hand-adjudicate every recorded leak, and publish the adjudication beside
        the raw log so a supervisor can re-score the same evidence.
    \end{itemize}
\end{enumerate}

\subsection*{6. Diagrams or Schematics (not included in 1,500 words)}

\noindent \textit{Runtime architecture of the AARAMSE middleware layer. Every
query is first put to the deployed model; only one it actually refuses enters
the repair path. The refusal-triggering fragment is localized, a certified
operator edits that fragment alone, and a re-probe confirms the user received an
answer --- otherwise the query escalates to a human. Operator certificates are
issued offline against the deployed model and enforced fail-closed. Every
decision is written to a hash-chained audit log.}
